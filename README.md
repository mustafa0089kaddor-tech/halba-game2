# حلبة — لعبة أسئلة جماعية بين فريقين

Next.js 14 (App Router) + TypeScript + Tailwind (RTL) + Supabase + Stripe. الاسم والشعار والألوان والأسئلة كلها أصلية.

> **حالة الكود:** كُتب كاملاً لكنه لم يُشغَّل بعد (لا شبكة أثناء البناء). متوقع أن تظهر أخطاء صغيرة عند أول `npm run build`؛ أصلحها أو أرسلها لي وأصلحها معك.

نصيحة تتفق مع ما كتبته: أطلق الفئات الخمس + الاشتراك أولاً، واجمع زيارات ومحتوى، ثم قدّم على AdSense، ثم أضف الباقات والرعاة عندما تثبت الأرقام.

## الإصدار الرابع: التحذيرات والحقوق وQR
- **أيقونات التحذير بلا كلمات:** 🕌 ديني (يتطلب تحقق المصدر)، 🎬 فيلم أو مسلسل، 👤 شخصية حقيقية. تُضبط من الأدمن لكل سؤال.
- **حماية الحقوق:** الوسيط لا يُعرض إلا إذا عُلِّم بـ🆓 (مرخّص) أو ✍️ (من إنتاجنا). أي وسيط بلا علامة أو محمي 🚫 يبقى مخفياً.
- **النسبة والترخيص:** تظهر تحت الوسيط مع أيقونة الحقوق.
- **رمز QR:** بعد كشف الإجابة يظهر رمز يقود إلى صفحة المصدر (ويكيبيديا مثلاً). يُولَّد عبر خدمة QR خارجية، ويمكن لاحقاً توليده محلياً.
- **أسئلة إضافية:** فئات بيكسار ومارفل.

## الصور والفيديو
يدعم كل سؤال صورة أو صوتاً أو فيديو (ملف أو رابط يوتيوب)، مع نسبة وترخيص تحت الوسيط. الطرق والتراخيص وما يجب تجنّبه في `docs/media-guide.md`.

## بنك الأسئلة وتقليل التكرار
**كيف يعمل السحب:** عند بدء اللعبة يسحب الخادم من كل فئة مختارة سؤالين من كل مستوى (٢٠٠/٤٠٠/٦٠٠)، أي ستة أسئلة. يفضّل الأسئلة التي لم تظهر لهذا اللاعب (يُحفظ ما رآه في المتصفح، وللمسجّلين في قاعدة البيانات أيضاً)، ولا يعيد سؤالاً رآه إلا إذا نفد غير المرئي في ذلك المستوى.

**الحجم المطلوب:** مع ٨ أسئلة لكل مستوى (٢٤ للفئة) تلعب الفئة نفسها ٤ مرات متتالية دون أي تكرار، وتتباعد التكرارات كثيراً بعدها لأن الفئات تتبدل بين الألعاب. الهدف إذن ١٢٠ × ٢٤ = **٢٨٨٠ سؤالاً** على الأقل، والأفضل ٤٨ للفئة. الفئة تصبح قابلة للعب عند ٢ على الأقل في كل مستوى، والباقي يظهر «قريباً».

**المولّد (يحتاج مفتاح Anthropic API وتدفع تكلفة الاستخدام):**
```bash
export ANTHROPIC_API_KEY=sk-ant-...
node scripts/generate-questions.mjs --group spacetoon --per-tier 8   # محور كامل
node scripts/generate-questions.mjs --cat nawawi --per-tier 12       # فئة واحدة
node scripts/generate-questions.mjs --all --per-tier 8               # كل الفئات (يستغرق وقتاً)
```
يُنتج ملف CSV في مجلد `out/`. ثم: لوحة الأدمن > **استيراد CSV**، ثم تبويب **الأسئلة** لمراجعة المسودات واعتمادها. المسودات لا تظهر للاعبين أبداً.

**قواعد المراجعة (مهمة):**
- **الأحاديث والسيرة وقصص الأنبياء:** لا تعتمد سؤالاً ديني دون مراجعته بنفسك أو بعرضه على مختص. النموذج قد يخطئ في الرواة والتواريخ. حقل المصدر يظهر للاعبين بعد كشف الإجابة، فلا تتركه خاطئاً.
- **المسلسلات والأفلام والأنمي:** تحقق من أسماء الشخصيات والممثلين وسنوات العرض، خصوصاً أسماء الدبلجة العربية.
- أي سؤال تبلّغ عنه اللاعبون يظهر في تبويب «البلاغات».
- البذرة المرفقة (١٦٨ سؤالاً) كتبتُها بحرص، لكن راجع الدينية منها أيضاً قبل النشر.

## ١) التشغيل المحلي (دقيقتان)
```bash
npm install
cp .env.example .env.local
npm run dev        # http://localhost:3000
```
بدون Supabase تعمل اللعبة ببذرة محلية في `src/data/bank.ts`: ٢٩٤ سؤالاً في ٤٩ فئة من الـ١٢٠ (الباقي يظهر «قريباً»). في هذه البذرة كل فئة فيها ٦ أسئلة فقط، فتتكرر نفسها في كل لعبة. لهذا نحتاج بنكاً أكبر (القسم التالي).

## ٢) Supabase
1. أنشئ مشروعاً في supabase.com.
2. SQL Editor: شغّل `supabase/schema.sql` ثم `supabase/seed.sql`.
3. من Project Settings > API انسخ `URL` و`anon key` و`service_role key` إلى `.env.local` (الأخير سري: لا يوضع في أي متغير يبدأ بـ NEXT_PUBLIC).
4. Authentication > URL Configuration: ضع `Site URL` ورابط `https://موقعك/auth/callback` ضمن Redirect URLs (وكذلك `http://localhost:3000/auth/callback`).
5. غوغل (اختياري): Authentication > Providers > Google، وأنشئ OAuth Client في Google Cloud وضع redirect الذي يعرضه Supabase.
6. سجّل دخولك بإيميلك مرة، ثم اجعل نفسك أدمن: `update profiles set role='admin' where email='بريدك';` وافتح `/admin`.

> الأمان: كل الجداول مقفلة بـ RLS، والخادم وحده (service_role) يقرأ الأسئلة، فلا يمكن لأحد جلب إجابات الفئات المدفوعة بمفتاح anon.

## ٣) Stripe
1. Dashboard (وضع Test أولاً) > Products: أنشئ منتج «اشتراك حلبة» بسعرين متكررين (شهري، سنوي)، وانسخ `price_...` إلى `STRIPE_PRICE_MONTHLY` و`STRIPE_PRICE_YEARLY`. اكتب نص السعر الظاهر في `NEXT_PUBLIC_PRICE_*_LABEL`.
2. لكل باقة موسمية: منتج بسعر **مرة واحدة**، ثم من `/admin?tab=business` أضف الباقة وألصق `price_...`، ثم اربط فئاتها بها من تبويب الفئات (يظهر زر الشراء في `/pricing` تلقائياً).
3. `STRIPE_SECRET_KEY` من Developers > API keys.
4. Webhook: Developers > Webhooks > Add endpoint: `https://موقعك/api/stripe/webhook`، الأحداث: `checkout.session.completed`, `customer.subscription.created`, `customer.subscription.updated`, `customer.subscription.deleted`, `invoice.paid`. انسخ `whsec_...` إلى `STRIPE_WEBHOOK_SECRET`.
5. فعّل Customer Portal من Settings > Billing > Customer portal (لزر «إدارة الاشتراك»).
6. محلياً: `stripe listen --forward-to localhost:3000/api/stripe/webhook` وبطاقة الاختبار `4242 4242 4242 4242`.
7. قبل الإطلاق الفعلي: بدّل المفاتيح إلى Live وأعد إنشاء الـ webhook.

## ٤) AdSense
AdSense **لا يعطيك إعلانات فور التسجيل**؛ يراجع موقعاً حياً. جهّز قبل التقديم:
- نطاق خاص (وليس vercel.app)، والصفحات القانونية الأربع (موجودة)، وصفحات الفئات فيها نص أصيل.
- زيارات حقيقية ومحتوى كافٍ. لا توجد عتبة رسمية، لكن المواقع الرقيقة تُرفض كثيراً. إن رُفضت حسّن المحتوى وأعد التقديم.
بعد الموافقة: ضع `NEXT_PUBLIC_ADSENSE_CLIENT=ca-pub-...` ووحدتين إعلانيتين في `..._SLOT_HOME` و`..._SLOT_ROUND`، وعدّل `public/ads.txt` بالسطر الذي يعطيك إياه AdSense.
الكود لا يحمّل أي سكربت إعلاني إلا بعد: ضبط المتغيرات + موافقة الزائر + أن لا يكون مشتركاً. لا إعلانات داخل شاشة السؤال.
إن كان لك جمهور في الاتحاد الأوروبي أو بريطانيا فتحتاج منصة موافقة معتمدة من Google (CMP) بدل الشريط البسيط الموجود.

## ٥) النشر على Vercel
1. ارفع المجلد إلى GitHub، ثم Vercel > Add New > Project > اختر المستودع (Next.js تُكتشف تلقائياً).
2. Settings > Environment Variables: انسخ كل متغيرات `.env.example` بقيمها، و`NEXT_PUBLIC_SITE_URL=https://نطاقك`.
3. Deploy، ثم اربط النطاق من Settings > Domains، وحدّث رابط الموقع في Supabase وStripe.
4. افتح الموقع على الجوال وأضفه للشاشة الرئيسية لتجربة الـ PWA.

## هيكل المشروع
```
src/app/            الصفحات: / ، /play ، /categories ، /pricing ، /sponsors ، /business ، /login ، /account ، /admin ، /e/[slug] + الصفحات القانونية
src/app/api/        checkout, stripe/webhook, portal, games, feedback, me, admin/import, admin/upload
src/components/play اللعبة: Setup, QuestionView, Results, PlayClient
src/lib/            data.ts (قراءة الفئات والصلاحيات)، stripe.ts، supabase/*، admin.ts
supabase/           schema.sql + seed.sql
scripts/gen_data.py        مصدر واحد للتصنيفات (١٢٠ فئة) وبذرة الأسئلة: يولّد catalog.ts وbank.ts وseed.sql
scripts/bank_batch*.py     دفعات الأسئلة (كل ملف دفعة). أضف دفعة جديدة بملف جديد ثم شغّل gen_data.py
scripts/generate-questions.mjs  مولّد مسودات الأسئلة (CSV)
```
لتعديل التصنيفات أو البذرة: عدّل `scripts/gen_data.py` ثم `python3 scripts/gen_data.py`، وأعد تشغيل `seed.sql`.

## ملاحظات صريحة
- حد الألعاب للزائر يُحفظ في متصفحه، فيمكن تجاوزه بمسح البيانات. هذا مقبول للبداية؛ المسجّلون محكومون من الخادم.
- أسئلة الفئات المفتوحة تصل جهاز المضيف (ضروري ليرى الإجابة). المقفلة لا تغادر الخادم.
- أي أسئلة تضيفها يجب أن تكون من تأليفك أو بترخيص، ولا تنسخ من مواقع أخرى. المسلسلات والأفلام وسبيس تون: الأسئلة عن حقائق عامة فقط، دون اقتباس نصوص أو كلمات أغانٍ.
- نقطة ضعف معروفة: واجهة السحب `/api/draw` مفتوحة للزوار، فمن يتعمّد يستطيع جمع الأسئلة بطلبات كثيرة. أضف حد معدّل (Rate limit) على Vercel إن صار هذا مشكلة.
- الصفحات القانونية قوالب. اعرضها على مختص قانوني، وعدّل مدد الاسترجاع حسب نظام بلدك.
- صوت وفيديو الأسئلة: ارفعها من الأدمن (تُرفع مباشرة إلى Supabase Storage). المدعوم: mp3/ogg/wav/aac وmp4/webm وصور png/jpg/webp/gif/svg.
